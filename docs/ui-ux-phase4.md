# UI・UX改善 Phase 4：グラフの見やすさ

2026年10月20日。ユーザーが次の段階として「グラフの見やすさ改善」を選択したため、この範囲に限定して実施する。調査基点はmain `65160a6`（v1.8.0）、専用ブランチは `codex/ui-ux-phase4`。変更前はNode 34件・Python/Playwright 66件、合計100件が通過した。

## 現状と問題点

体重・放鳥・食欲・フン・活動量のグラフは、SVGの中に軸文字が含まれていた。軸の指定は9〜11のviewBox単位で、画面幅に合わせSVG全体を縮めると、実際の文字も小さくなる。文字だけを拡大すると、軸の余白が足りず描画部分に重なる。

点の値は主にホバー時のタイトルで確認する形式で、iPhoneでは日付と値を確かめにくい。健康の「気になる」は既存の非数値・注意点として表示されており、正常値に変換すべきではない。

## 実装した改善

- 軸文字をSVGの外のHTMLで表示する。通常は12.25 CSS pxで、画面幅に合わせて文字まで縮小しない。
- 軸の列幅をラベルの長さに合わせ、描画部分と文字を分ける。文字拡大に合わせてグラフの高さも広がる。
- SVGには線と目盛りを描き、文字と点の印は画面上の大きさを保つ。体重・健康はピンク、放鳥はグリーンの既存の配色を保ち、線の背景とのコントラストを3以上に調整する。
- 体重にg、放鳥に分を明示する。健康の目盛りは「少なめ・いつもどおり・多め」で表示する。
- 「記録点の値を一覧で見る」を追加する。日付と数値・状態を確認でき、閉じればグラフ中心の表示を維持できる。
- 数値の点のタイトルは維持し、ホバーできる端末では値を確認できる。iPhoneなどでは一覧でも確認できる。
- 「気になる」は ! と一覧の状態名で表示し、正常値や数値に置き換えない。注意点をまたいで線をつながない。
- 記録がない期間には既存の空状態を表示し、空白の日に0や正常値を補わない。

新しい診断・健康スコア・推奨体重・クラウド処理・ライブラリは導入しない。ホーム、写真、5つの下部ナビ、タイマー、Phase 3のバックアップ・通知UIは変更しない。

## 集計・データへの影響

`M.chartData` の返すデータをそのまま利用する。体重は同日の最後の記録、放鳥は同日の合計、健康は従来の保存値による観察値を表示する。期間切り替えと記録点を結ぶ意味を変えない。

一覧はグラフの記録点の一覧であり、元の全測定記録ではない。同日に複数の体重があれば最後の値が一覧にも表示され、元の全記録は従来の「一覧」から引き続き確認できる。元の記録を削除したり、集計値を書き戻したりはしない。

`model.js`・`platform.js` は未変更。DB名 `kozakura-biyori-local-v1`、DBバージョン1、公開URL、バックアップ識別子とv1/v2形式を維持する。健康の保存値は従来の4種類のままで、「未確認」などの新しい値は追加しない。写真・動画・飼育記録を外部送信しない。合成データの独立した保存領域だけで検証し、実際のリリィのデータは読まない。

## 自動テストと目視確認

新規6件で次を検証する。

1. 同日の最後の体重・放鳥の合計・単位と、記録を変更しないこと。
2. 食欲・フン・活動量の既存4状態、注意点で線を切ること、空白日を補わないこと。
3. 320/390/402px・文字100%/200%で、軸文字が12px以上・注意印が14px以上であり、描画部分や日付と重ならず横にはみ出さないこと。
4. 期間切り替え・体重専用ページと、実際の記録点だけの表示。
5. 記録なし・すべて「気になる」の場合に、架空の数値や正常値を作らないこと。
6. オフラインでの表示、旧v1/現v2バックアップの記録値維持。

線の背景とのコントラストを計算し、通常の軸文字・単位・一覧・注意印を含む健康/体重の画像をChromiumで目視確認する。変更後のNode 34件・Python/Playwright 72件、合計106件がすべて通過した。グラフの6件に加え、既存の記録・写真/動画・タイマー・バックアップ復元・通知案内・アプリ更新を含むテストも通過している。最終のグラフ確認では7日・30日・3か月・1年の切り替え、点のタイトル、線と背景のコントラストを再確認した。小画面・文字200%・目視確認はChromiumで行い、iPhone実機では未確認。
