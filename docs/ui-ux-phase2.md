# UI・UX改善 Phase 2

基点はmain `e5fc7ab`（v1.5.1）。`codex/ui-ux-phase2` ブランチで実施。Phase 1のNode 31件・ブラウザ37件を開始前に確認した。実データではなく、独立したブラウザ保存領域の合成プロフィール・写真・動画・記録を使用する。

## 変更内容

| 対象 | 変更 | 維持した機能 |
| --- | --- | --- |
| ホーム | 今日の予定・今日のお世話・未実施バナーを一つのカードに整理。予定ごとの状態と、ほかのお世話を表示 | 写真の大きさ・レイアウト・拡大率・範囲・コメント、健康、放鳥、4タイル、5つの下部ナビ |
| 体重 | 入力画面の前回値と年月日、decimal入力指定、上部の記録ボタン、表示切替の名前を追加 | 今回の実測値は空欄。g単位、入力範囲、グラフと一覧。診断はしない |
| 行動 | 選択日の12項目それぞれに記録回数を表示。追加した直前の1件を15秒以内に取り消せる | 12項目の名前と絵、順番と色、過去の独自行動、かじり跡への入口 |
| カレンダー | 件数・今日の囲み・選択中の✓、今日へ戻る、選択日への種類別追加 | 月移動、過去日、記録の表示・編集・削除、お世話記録 |
| アルバム | 見える追加ボタン、追加後の写真/動画タブへの切替、詳細画面のお気に入り操作、種類別件数 | 写真と動画の形式・上限、動画プレイヤー、削除前確認 |
| イラスト | 「イラスト変更」に名称を統一し、見た目の変更であることを明示 | コザクラ／ボタン各6配色、写真の優先。複数羽機能は追加しない |

通常の「写真」タブはかじり跡を除く写真、「かじり跡」は分類済みの写真、「お気に入り」は通常・かじり跡・動画を含む。表示の整理であり、写真配列からの削除や複製ではない。写真の分類を外すと通常の写真に戻る。詳細画面でお気に入りを変更しても、未保存のメモや日付を作り直さない。

予定のある日は予定枠、ない日は通常のお世話を同じカードに表示する。追加記録は「追加・過去の記録」から行える。毎日の実施時刻の扱い、朝夕枠、取り消しの対象ID照合はPhase 1と同じ。通知の予約方式は変えない。

## データへの影響

`model.js` と `platform.js` は未変更。IndexedDB名 `kozakura-biyori-local-v1`、公開URL、v1/v2バックアップ、健康の保存値とグラフ、タイマーの計測・確認、写真100件・動画8MB・全体約38MBの上限を維持した。取り消しは既存のID・内容一致による1件削除を行動にも再利用する。お気に入りの変更は保存成功後に表示し、二重クリックと保存失敗を扱う。

## 変更ファイル

- `app.js`: 既存画面と操作の整理。
- `style.css`: 統合カード、回数、日別件数、追加ボタン等。
- `index.html` / `sw.js`: バージョンv1.6.0とオフラインキャッシュ。
- README / 本文書: 操作と影響範囲。
- `tests/test_behaviors.py`: 意図したラベル変更のみ調整。
- `tests/test_phase2_ux.py`: Phase 2の受入確認。
- `tests/fixtures/bird-color.mp4`: 自作の単色32px・0.4秒動画。実データではない。テスト実行時にffmpegは不要。

## 確認項目

統合カードと写真設定、予定枠と取り消し、前回体重・空欄入力・保存結果、行動回数と過去日、カレンダーの件数・今日・過去への追加/編集、アルバム分類・お気に入りと未保存メモ保持、写真/動画のアップロード・動画メタデータ、保存容量エラーと再試行、オフライン、v1/v2互換、320px/390pxと文字200%を合成データで検証する。

iPhoneの実際の数値キーボード、写真ライブラリの選択、動画コーデックの再生、文字拡大、画面ロックやカレンダー通知は実機確認が必要。クラウドのChromium確認をiPhone実機確認と扱わない。

## 次に残す項目

Phase 3のバックアップ書き出し/保存完了の区別、復元前確認表示、お世話通知の3段階案内は今回未変更。健康記録の新しい保存値、複数羽、課金、App Store公開、ネイティブ通知の実装も対象外。
